## 1. Principles

- Every meaningful feature ships with tests in the same milestone.
- Unit tests make no network calls, need no API keys and need no model downloads (fakes: `HashEmbedder`, `FakeProvider`, `SpyProvider`, `FakeReranker`).
- Failing tests are never skipped silently. A skip is allowed only for a missing prerequisite (e.g. no `TEST_DATABASE_URL`), with an explicit reason that shows up in the test report. CI provides every prerequisite, so nothing is skipped there.
- Test results are reported as actually run: exact command and output.
- Fixture PDFs are generated by code (no committed binaries of unknown origin) and are deterministic.

## 2. Test levels

| Level | Scope | Location | Markers | Runs in |
|---|---|---|---|---|
| Unit | Pure functions/classes: normalization, chunking, IDs, metrics, RRF, prompt builder, citation validator, JWT, hashing | `tests/unit/` | (none) | every commit |
| Integration | Real PyMuPDF, real FAISS persistence, JSONL store; PostgreSQL repositories + Alembic (M5+) | `tests/integration/` | `integration`, `db` | every commit (CI with a Postgres service) |
| Model | Real Sentence Transformers / cross-encoder | `tests/integration/` | `slow` | CI nightly / manual |
| API | FastAPI app via `httpx.AsyncClient` + `ASGITransport`, fake LLM, test DB | `tests/integration/api/` | `api`, `db` | every commit |
| Security | Regression suite SEC-01..12 | `tests/security/` | `security` | every commit |
| E2E | Docker Compose stack + smoke script; manual UI checklist | `tests/e2e/`, `scripts/smoke_test.py` | `e2e` | M6 release / manual |
| Live LLM | Real Gemini calls (small set) | `tests/live/` | `llm_live` | manual only, needs `GEMINI_API_KEY` |
| Evaluation | Retrieval/generation evaluation + regression compare | `insureassist eval …` | — | CI (offline parts) from M4 |

Default `pytest` run: `-m "not slow and not e2e and not llm_live"`.

## 3. Database testing

- Integration tests use **real PostgreSQL** (same major version as production, 16), not SQLite, because the schema relies on partial unique indexes, `jsonb`, `inet` and `timestamptz`.
- Locally: `docker compose up -d postgres-test` (M5) and `TEST_DATABASE_URL` set. In CI: a GitHub Actions service container.
- Isolation: one schema migration per session (`alembic upgrade head`); each test runs inside a transaction that is rolled back.

## 4. Coverage and quality gates

| Gate | Threshold | Tool |
|---|---|---|
| Line coverage, `src/insureassist` (UI excluded) | ≥ 80% (≥ 90% for `auth`, `retrieval.hybrid`, `generation.citations`) | `pytest-cov` |
| Lint and format | zero findings | `ruff check`, `ruff format --check` (including the `S` security rules) |
| Types | zero errors on `src/` | `mypy` (strict for new modules; third-party stubs where available) |
| Dependency audit | no known high/critical issues without a recorded exception | `pip-audit` (M6) |

## 5. Test catalogue by milestone

### M1 — Ingestion

| ID | Test |
|---|---|
| TS-ING-01 | Valid 3-page fixture: page *n* text is on page *n* only |
| TS-ING-02 | Normalization rules (NFKC, soft hyphen, de-hyphenation, whitespace), table-driven |
| TS-ING-03 | Chunk size ≤ max, overlap ≈ configured, min-fragment merge, no cross-page chunks, `overlap ≥ size` rejected |
| TS-ING-04 | `char_start`/`char_end` slice the page text to exactly the chunk text |
| TS-ING-05 | Deterministic IDs: two runs give identical documents/chunks JSONL (byte-equal) |
| TS-ING-06 | Duplicate: second ingest of the same bytes gives `duplicate` and no new records |
| TS-ING-07 | Malformed: not-a-PDF, truncated, encrypted, zero-page, oversized, too many pages → specific error codes, no residue |
| TS-ING-08 | Empty/scanned: `no_extractable_text`, `likely_scanned` page warnings |
| TS-ING-09 | Report schema validation; CLI exit codes |
| TS-ING-10 | JSONL round-trip through the Pydantic models |

### M2 — Retrieval

| ID | Test |
|---|---|
| TS-RET-01 | Embedder output shape and unit norm (fake + `slow` real) |
| TS-RET-02 | FAISS add/search/remove; persist → load gives identical results |
| TS-RET-03 | Atomic write: a simulated crash mid-write leaves the old index loadable |
| TS-RET-04 | Rebuild from canonical store equals the incrementally built index (ID set + top-k) |
| TS-RET-05 | `vector_id` derivation is deterministic; a forced collision fails the build |
| TS-RET-06 | BM25 tokenizer cases; exact rare term in the top 3 |
| TS-RET-07 | RRF against hand-computed fusion; deterministic tie-breaking |
| TS-RET-08 | ACL selector: results come only from allowed documents, even when disallowed ones score higher |
| TS-RET-09 | Deleted document's chunks never returned; manifest mismatch → `stale` |
| TS-RET-10 | Metric functions (Recall@k, MRR, nDCG) against hand-computed examples |

### M3 — Generation

| ID | Test |
|---|---|
| TS-GEN-01 | Prompt snapshot: system instructions separate, evidence delimited and labelled |
| TS-GEN-02 | Delimiter-injection text in a chunk is neutralized |
| TS-GEN-03 | Structured output parsing; invalid JSON → one retry → safe error |
| TS-GEN-04 | Abstention: no evidence (LLM not called), model reports insufficient, zero valid citations |
| TS-GEN-05 | Conflicting evidence status and citations |
| TS-GEN-06 | Timeout/5xx/429 from the provider → bounded retries with backoff → 503 `llm_unavailable`, sanitized |
| TS-GEN-07 | Gemini adapter maps configuration (model, temperature, max tokens, timeout) correctly (SDK client mocked) |

### M5 — API, auth, UI

| ID | Test |
|---|---|
| TS-AUTHZ-01 | Endpoint × role matrix (parametrized from [api-specification.md §3](api-specification.md)) |
| TS-API-01 | Each endpoint's response validates against its documented schema; the OpenAPI snapshot matches |
| TS-API-02 | Error envelope and `X-Request-ID` on every error type |
| TS-API-03 | Upload → poll → ready → query → cite → feedback → delete → query no longer returns it |
| TS-API-04 | Startup reconciliation of `processing`/`deleting` documents |
| TS-DB-01 | Alembic upgrade/downgrade on an empty DB; constraint tests (grant check, unique checksum) |
| TS-AUD-01 | Audit events written for each listed action |
| TS-UI-01 | UI API-client helpers + plain-text render helper (unit); manual UI checklist in [runbook.md](runbook.md) |
| SEC-01..12 | Security regression suite ([security-controls.md §5](security-controls.md)) |

### M6 — Release

| ID | Test |
|---|---|
| TS-E2E-01 | `docker compose up` from clean → health ready → smoke script (login, upload sample, query, delete) |
| TS-E2E-02 | Restart containers → data and index persist → the same query gives the same citations |
| TS-E2E-03 | Backup → wipe volumes → restore → rebuild index → smoke passes |
| TS-E2E-04 | Image inspection: no `.env`, keys or `data/` baked into the image |

## 6. Requirement traceability

Each FR/NFR ID in [requirements.md](requirements.md) maps to at least one TS/SEC test above. From M1 onward, test functions reference their IDs in docstrings (e.g. `"""TS-ING-05 / FR-ING-05"""`), so the mapping can be listed with `grep`.
